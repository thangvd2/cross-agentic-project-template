# Financial Model

Vault Core's financial model defines how the system records movements of funds ([[concept-postings]]) to derive an account balance at any point in time.

## Source of Truth vs System of Record

Vault Core acts as a ledger that stores an ordered list of fund movements.
- **Source of Truth**: Postings where Vault Core is the ultimate decider of the funds' state (e.g., internally triggered interest accruals or external authorisation requests where Vault Core ringfences funds).
- **System of Record (SoR)**: Postings where Vault Core simply records movements that happened outside of its control.

## Time and Order

Every posting features three distinct timestamps, allowing Vault Core to provide different balance time-series:
- **Ledger balance**: Based on insertion time (immutable).
- **Product balance**: Based on value time (mutable by backdated/future-dated postings).
- **Reporting balance**: Based on booking time (mutable).

## End of Day (EOD) Process

The EOD process calculates the position of all accounts at the end of a banking day. It involves several key concepts:

- **Business as usual (BAU)**: Normal customer activity (e.g., card purchases) that continues uninterrupted during EOD.
- **1º cut-off**: The boundary between banking days (often midnight), used as the reference point for balance calculations.
- **2º cut-off**: The point when EOD processing actually begins. After this point, postings cannot be backdated to affect the 1º cut-off balance.
- **Grace period**: The time between 1º and 2º cut-off where late-arriving postings can still be backdated to the 1º cut-off.
- **Overnight postings**: Postings generated by EOD scheduled jobs (interest/fees) that execute after 2º cut-off.
- **Completion**: The moment all EOD processing finishes.

### Reaching an EOD Position

There are two main strategies for attributing overnight postings to a banking day:
1. **At the 2º cut-off**: `Day 0 BAU + Day 0 Overnight postings`. The bank must wait until Completion to calculate the position.
2. **At the 1º cut-off**: `Day 0 BAU + Day -1 Overnight postings`. The bank can calculate the position immediately at the 1º cut-off.

### Typical Implementation

EOD is typically implemented via a 6-step flow involving Vault Core's Scheduled Events and Account Schedule Tags. Streaming APIs populate a Data Hub, which reconciles events and listens for an `OperationEvent` signaling the completion of tagged EOD schedules before generating reports.
